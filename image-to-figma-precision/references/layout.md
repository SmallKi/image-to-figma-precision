# 排版准确与无溢出

默认检查参考的空间关系和内容完整显示，不依赖逐像素评分。

## 建立布局

先按 [asset-assembly.md](asset-assembly.md) 确定语义父容器和变换归属。共同标题线上的前置图形、中文、英文、分隔线与端点先组成 Header，再排局部坐标；复用 Header 校准另一行。按钮/标签先在 0° 下组合生成的无字背板与原生文字，最后整体旋转。局部绝对定位不等于节点散放在屏幕根部。

- 从原尺寸确定画布、主要面板、列宽、标题区、按钮区和留白。记录共同左右边线、文字基线、等距行列与视觉中心；有意错位的装饰不强行对齐。
- 先校准主要区域和一行代表内容，再复用。避免持续移动单个对象导致整体间距漂移。
- 字体加载后再量文字，将字重、字号、行高、字距、换行和框尺寸一起判断，不能只凭字体名称或框宽认定排版正确。
- 图标在约定框内等比缩放，校准主体视觉中心和标签关系；透明画布居中不等于主体居中，不能拉伸图标或挤压相邻文字。按钮/标签按 asset-assembly.md 区分 canvasSize、bodyBounds、contentRect：先将实际背板适配目标框，再按可用区排字，不能以整张 PNG 的外框计算按钮大小或文字中心。

## 最终检查

1. **文本内部**：整段文字、最后一行、上下升降部、描边和阴影完整显示，数值与单位有合适间距。固定高度 TEXT 可能隐藏超出内容；核对实际文字高度和换行，必要时在临时副本以相同宽度、字体和内容自动计算高度后比较，不能只查外框。按钮文字还需检查可见字高与实际背板高度的比例、字重和字距；行框居中或无溢出不等于字面协调。本地字体预览不能替代 Figma 原生 TEXT 的最终导出。
2. **容器内部**：标题、数值、图标和按钮处于允许的内容范围并保留内边距。按钮检查文字是否位于背板真实 contentRect/labelRect 的视觉中心，左右/上下字面留白是否符合参考；有图标时核对整体居中或剩余区居中的依据。透明外边不算内边距，分离装饰不决定主背板中心。检查所有祖先的 `clipsContent` 和遮罩，避免内容已经被裁掉却误判“无溢出”。
3. **组件之间**：行列间距稳定，标题正文层级正确，数字不压边框，按钮文字不撞图标，卡片无非预期重叠。检查同组标题的图形视觉中心、中文/英文基线和分隔线关系；“都在一个组”不等于已对齐。旋转组件同时查看背板长轴和文字基线，避免底板烘焙倾斜、文字水平或重复旋转。
4. **画布边缘**：背景覆盖完整，无意外裁切、漏边或内容超出根框。参考中已有的阴影、发光、贴边人物和悬浮徽章可有意出界，记录允许范围，不误删，也不无限放大容器来掩盖问题。
5. **实际结果**：查看最终 1× 导出，重点检查最窄容器、最长文案、最大数值和末行/末列。语义组在临时副本移动一次，确认前置图形、文字与线条一起移动；旋转类组件保留 0° 与放置角度两张导出。可编辑或响应式组件按约定的最长文案与最小尺寸测试；静态截图任务不扩展成无边界的响应式设计。

## 边界诊断

在同一坐标系中比较内容和父容器边界；旋转/变换节点使用变换后角点。`absoluteBoundingBox` 可辅助几何检查，`absoluteRenderBounds` 可辅助描边/阴影检查，但都不能单独证明固定文字框未截字。区分允许的装饰出界与功能内容出界，不机械拒绝所有超出绘制范围。

现有 audit-figma.js 是结构辅助审计，不自动检测全部溢出，仍须查看实际渲染。

## 修复顺序

先排查字体加载、意外换行、行高和固定文字框，再校正局部宽高、内边距、间距或定位。修复后重看整屏和相邻区域，保留原阅读节奏。

不得靠删字、随意省略、横向压缩字体或开启裁剪隐藏错误。参考本就要求的省略、遮罩和滚动属于有意设计，正常保留。

记录 `layoutAccurate`、`noUnintendedOverflow`、已检查区域和证据；有意出界放入 `intentionalOverflow`，仍有问题写具体节点和位置。通过即停止，不做没有视觉收益的逐像素搜索。
