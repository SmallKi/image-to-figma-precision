# 生成前拆零件，组装时恢复关系

本流程用于所有美术图形，先于提示词和 Figma 节点创建执行。先提交到任务记录的拆解表，不额外等待用户审批；不确定处记录依据和置信度。

## 1. 定义生成单位与来源

列出每个可见美术对象的 `key`、`assetKey`、`assetMethod`、参考区域、目标主体尺寸、`parentKey`、`sharedPartKey`（如有）、`canonicalPose`、`placementRotation`、`transformOwnerKey`。文字独立登记为原生 TEXT。

所有可见图形都通过参考图生图，包括简单菱形、线形装饰、纯色剪影、按钮与标签底板。不能用代码绘制可见 SVG/path、多边形、填色矩形或 Figma 原生图标代替。技术容器、布局、裁剪遮罩、旋转/缩放仍由 Figma 完成；图像承载矩形使用生成图片填充。遮罩只能裁剪已生成/用户指定素材，不承担可见的造型绘制。用户明确要求源像素或现有资产时逐项记录例外依据。

小图形也先看其完整参考，描述可识别的轮廓和结构。例如帽檐、帽尖、折角和装饰不能用“金色花饰”泛化；不确定主体时保留外形线索并标注语义未知，不能生成一个无关的简笔轮廓。时间或生图预算耗尽时保存待完成项，不能临时用手画图形填满并宣称完成。

## 2. 先查重，再写提示词

把相邻或同功能对象放在一起看：轮廓、边框层次、角点、纹理布局和相对尺寸相同，只有中央物体不同，通常是“共用 UI 背板 + 独立前景”。轻微旋转、遮挡、缩放及光照差异不自动构成新底板。不能只按整张图标轮廓查重。

- 共用背板：生成一次空白母版，不含物体、文字、数字或每个实例特有的徽记；建立一个主组件并记录它的 `sharedPartKey`。
- 独立前景：逐个生成透明物体，提示词明确排除共用底板/边框/背后徽章。物体自身组成部分保留，例如书封面与奖杯底座；不能因为轮廓相似就删除它们。
- 不确定的重复候选：记录两处以上参考区域及相同/不同证据，先校准代表底板。颜色或状态确有差别时在同一组件族中记录变体依据，不重复生出无关的基础轮廓。
- 组装：`Item instance → Backplate instance + Foreground instance + optional native TEXT`。每个前景和背板都可分别隐藏。只把一张带背板的完整图标塞进 Item，不算分离。

例如四个技能项应先判断是否复用同一背板；若成立，交付一个背板资产加四个前景资产。不能把共用金框写成每个物体的“固有底座”随四个物体各生成一次。

## 3. 区分造型、透视与摆放旋转

`canonicalPose` 描述素材自身的视角/姿势，`placementRotation` 描述整个 UI 单元相对页面的旋转。水平按钮两端斜切不代表整个按钮旋转；卷轴在徽章内的斜放或书籍透视也不自动变成父容器角度。

对于整块倾斜的按钮、标签、标题牌：

1. 依据长边、装饰轴线、文字基线等共同线索估计摆放角度，记录置信度；不要用斜切短边单独推断。
2. 生成规范母版：正对画布、长轴水平、整体摆放角度为 0°、无字。保留原有斜切端头、纸张卷边与材质。提示词指出参考中的页面倾斜将在 Figma 中恢复。
3. 在 0° 的共同父容器内放背板、图标和原生文字，对齐局部基线和内容框。
4. 只旋转该父容器或其最终实例一次，让背板、文字、装饰一起变化。子层通常保持局部 rotation=0；确有独立姿势的前景按参考记录局部例外。不要为了让字水平而反向抵消父旋转，除非参考有明确证据。
5. 检查实际图像的长轴。节点 rotation=0 不证明母版摆正；不能把烘焙倾斜的素材当作 0° 资产。若母版仍整体歪斜，先修素材或有证据地校正素材方向，再组装，避免重复旋转。

对透视平面，单次旋转无法复现透视；保留素材视角并按局部文字承载面规划，记录近似。不得把原生文字栅格化来掩盖透视差异。

## 4. 从语义单元向外组装

### 按钮主体边界与文字可用区

图片画布、可见按钮、文字可用区是三个不同的框。生成前按参考记录主体宽高比与文图比例；收到素材后测量实际结果，不能把提示词要求当作结果尺寸。

- `canvasSize`：整张母版尺寸。透明外边只用于安全保存，不是按钮内部留白。
- `renderBounds`：全部合法绘制范围，含柔边、必要阴影与分离装饰；用于避免裁坏素材。
- `bodyBounds`：按钮承载文字的主背板边界，排除外部投影、飘带末端和分离闪光。不能把所有 Alpha 的外接框或不对称装饰的质心直接当作按钮中心。
- `contentRect`：0° 组件局部坐标中的可用内容区，在实际背板内部避开边框、斜切/卷角、厚重装饰。记录它的坐标系、推导依据与置信度；以参考的内边距和视觉轴线确定，不规则形状还须目视检查四角和文字附近的真实轮廓。不能把源图像素坐标、母版像素坐标和组件局部坐标混写成同一组数值。

**先解决外部空隙。** 生成时选择接近主体比例的画幅，要求主体大幅占据画布、小幅且大致均匀的四边安全边距。普通无外发光背板可从主体长轴占画布对应边约 90–96%、每端约 2–5% 留边开始，按实际参考与部件调整；这是构图起点，不是强制裁切阈值。若工具只支持固定比例，横向长条在短轴上剩余空白是画幅限制，不能拉高按钮去填满，也不为这一点无限重生。

保留原始母版。对已验证真 Alpha 的素材，可用环境允许的工具生成紧边派生文件：只去掉确认全透明的外部空行/列，保留全部合法 `renderBounds` 及少量安全像素，记录 `cropOffset` 和新文件哈希；不得截断阴影、柔边、卷角或分离零件。若沿用未裁母版，就根据 `bodyBounds` 计算图像承载节点的缩放与偏移；两种方式都应使组件外框对应目标按钮，而不是 PNG 画布。RGB/烘焙棋盘格不能用这种裁边伪装成透明；主体本身比例错误或像素不足，应按预算修正生成，不靠裁边或插值掩盖。

设母版主体框为 B=(bx,by,bw,bh)，0° 组件内目标主体框为 T=(tx,ty,tw,th)。保持比例时：

```text
s = min(tw / bw, th / bh)
imageX = tx + (tw - s*bw)/2 - s*bx
imageY = ty + (th - s*bh)/2 - s*by
imageWidth = canvasWidth*s; imageHeight = canvasHeight*s
```

该式用于完整母版承载节点，里面的图片也必须按原始宽高比显示；不要再给图片做一次 FILL 裁剪或 FIT 留白。公式只证明已测主体框能映射到目标框，不能证明主体宽高比正确。先比较 `bodyBounds` 宽高比与参考；明显偏差属于素材失败，不能靠等比适配、非等比拉伸或排字掩盖。采用紧边派生图后，B 和所有素材坐标都先减 `cropOffset`，不得重复扣偏移。背景素材像素坐标与 `contentRect` 的组件局部坐标不可混用。

**再解决文图协调。** 根据参考选择字形、字重、文字颜色/描边和“可见字高 ÷ 实际背板高度”，校准代表文案后复用。不能用 PNG 高度推字号，也不能只满足“不溢出”就认为协调。按钮主体若实际只占画布高度的三分之一，按画布排文字就会错误；先修素材适配，再处理字号和字位。

- 只有文字时，以 `contentRect` 的视觉中心放置字面。TEXT 的行高、上升部/下降部和内置留白不等于实际字面；居中对齐属性只能作为起点。
- 有动作图标时，按参考判断“图标+文字整体居中”还是“图标固定、文字在剩余区域居中”。前者先确定两者总宽与间隔，再整体置于可用区；后者明确扣除图标占位和间隔得到 `labelRect`。不能把文字居中到整个背板后再硬塞图标。
- 看实际渲染的字面上下/左右留白和基线。必要时临时导出原生 TEXT 得到可见字面框，不将正式文字转曲或栅格化；字面框须包含描边、阴影等实际视觉效果，并记录栅格原点。Figma 的文字外框/`absoluteRenderBounds` 不单独证明字面居中。
- 从截图估计参考字面时，单一“暗色像素阈值”只能作辅助：浅色笔画、高光、描边和纸张纹理可能被漏掉或误收。结合颜色/局部对比、连通形状和人工 1× 复核；无法可靠自动分割时记录语义边界与误差范围，不能用漏笔画的框校准文字中心或字号。
- 若相对 TEXT 原点的实际字面框为 I=(ix,iy,iw,ih)，需居中的区域为 S=(sx,sy,sw,sh)，则 `textX=sx+(sw-iw)/2-ix`、`textY=sy+(sh-ih)/2-iy`。不对称背板可按参考加小幅 `opticalOffset`，记录依据；不能以视觉微调之名补偿尚未处理的大面积透明边。
- 在 0° 下完成字面比例、图标间隔与光学居中，再旋转共同父容器。字体候选的本地渲染只用于缩小范围；最终字面框、基线和间距必须在实际 Figma 字体与导出中复核。禁止横向压字、删字、随意缩小或开启裁剪隐藏问题。

### 语义单元

在生成前识别共同移动和共同排版的成员。距离近是线索，还要结合功能、共同轴线、同一分隔线和重复关系。

- 标题行：前置菱形/图标、中文标题、英文副标题、分隔线及端点装饰属于同一个 Header 容器。中文与英文按参考的字面基线，图标按视觉中心对齐；不是所有对象 y 相同。
- 属性行：图标、名称、数值、背板属于一个 Row，重复行复用 Row 主组件。
- 资源项：图标、数字、加号属于一个 Resource；按钮底板、动作图标、标签属于一个 Button。
- 若标题行存在非均匀间距，可在同一 FRAME 中用局部绝对坐标；不能因为不用 auto-layout 就省略父容器。

重复标题行优先同一组件：间距和视觉对齐校准代表项后复用。不能只把两个松散的标题分别包装成组，而没有把前置图形纳入共同布局。

## 5. 验证决定是否可扩展到全组

每类新结构抽查一个代表项，保存实际证据与 manifest 关系：

| 问题 | 生成阶段证据 | 组装阶段证据 |
| --- | --- | --- |
| 手画美术替代 | 实际生成调用、母版哈希、对应参考；帽子轮廓与按钮材质目标尺寸目视检查 | 可见图形来源可追溯；技术 mask 与可见绘图区分，不能只按 RECTANGLE 节点类型判断 |
| 底板斜、文字正 | 0° 母版目标尺寸图与长轴检查 | 导出 0° 组件与放置角度实例；检查背板轴线、文字基线及共同父变换，没有重复旋转 |
| 紧凑行散落 | 拆解表列出语义成员和共同 parentKey | 临时副本移动整行，所有成员一起移动；改标题后间距/基线仍按约定，观察图形中心而非透明框中心 |
| 共用背板烘焙 | 单独空背板与各透明前景的换底图 | 各实例指向同一背板主组件；隐藏前景仅留同一背板，隐藏背板只留前景；不能在前景 PNG 中再带一层背板 |
| 大空白与文字偏位 | 记录母版画幅、主体占比及四边空隙；主体比例正确，裁边保留合法绘制内容 | 在 QA 叠加 canvas/body/content/字面框，确认按主体适配、按可用区排字；去掉辅助框再查看目标 1× 和最终旋转导出，核对字高、内边距及图标间隔 |

结构与来源可检查，画风、烘焙角度、背板分离和文字视觉居中仍必须看图。计划或本地模拟不能声称 Figma 实测；无实际生图结果也不能仅凭提示词把素材标记通过。默认 8–9 分相似度不豁免上述错误。
