# 透明图标与边缘验收

图标的前景（麦穗、石块、建筑、人物等）与承载它的按钮/彩色圆角底板必须分开。贴着原底板时看似正常，不能证明背景已去掉。

## 提取与保真

优先采用用户提供的原始透明素材，或用 Figma 原生矢量轮廓遮罩保留截图中的前景像素。只有矩形、椭圆、圆角框等粗裁剪时不能宣称完成。复杂位图去底/补画使用图像编辑工具，并检查输出实际文件，不相信提示词中的“transparent”。遮罩要处理外轮廓和内部孔隙，如麦穗之间、杯把、工具握柄之间的空隙。

不能按一个背景色全局删像素：纸张、金色高光、皮肤等可能与底色接近。先根据对象边界分割，再检查边缘的底色污染。只收缩轮廓会损失细枝、发丝和描边；黑底露白边、白底露黑边或原底板的彩边都算失败。必要时重新生成局部透明素材，但必须再比对轮廓、纹理、尺寸及方向；不允许用重画后变形的图标换取干净边缘。

头像的圆形肖像画面可以保留其内部绘画背景，但头像外部应透明，原图中烘焙的等级数字和徽章须去掉并以独立原生层重建。图标自身的纸张、盾牌、建筑台基属于前景，不应误删。

实体接近不透明和自然柔边可以接受：例如 Alpha 253/255 不算去底失败。严格 255 像素很少时，先看 Alpha 分布、近不透明比例、核心与高光锚点及真实底板效果；不因半透明像素总数多而强制硬化 Alpha。明显透底、丢失高光或混入旧底色仍需修复，见 [transparent-generation.md](transparent-generation.md)。

## 检查顺序

每个素材固定执行八步闭环：原图配准 → 标注 `keep/holes/outside` → 生成至少两种 Alpha 候选 → 运行语义与拓扑合同 → 生成多底色证据图 → 按缺陷类型只改一个因素 → 写入 Figma 主组件 → 导出主组件 4× 与整稿三态回归。任何一步失败都保留失败样本和哈希，回到对应步骤，不把“默认画面看不出变化”当作通过。

运行 `scripts/render-cutout-proof.py icon.png --out proof.png --zoom 4` 可生成白、黑、洋红、青色、Alpha 灰度和半透明边缘图。普通图标优先直接从 Figma 导出 4× 再以 `--zoom 1` 检查，避免本地放大掩盖 Figma 的真实采样。黄色只表示部分 Alpha 的位置，不表示它自动合格；连续锯齿、旧底色环、高光断裂和孔洞填实仍需与原图对位判断。

出现边缘污染时，先按 [edge-cleanup.md](edge-cleanup.md) 识别污染来源、准备独立图标参考，并使用局部边缘修复模板。检查范围包括半透明带、贴着它的 Alpha=255 实体边沿和孔洞内沿；只检查已知底色距离会漏掉混色。

### 四类缺陷分开处理

| 缺陷 | 检测证据 | 修复方式 |
| --- | --- | --- |
| 锯齿、截断、轮廓漂移 | 1× 对位原图；4× 三底色检查；检查 Alpha 边界是否只有 0/255 | 根据原轮廓拟合连续曲线或重新抠图，限制曲线偏移；不能以整体模糊掩盖锯齿 |
| 白边、黑边、旧底色残留 | 黑底显浅边，白底显深边，互补色底显彩边；检查原底色与边缘颜色的关系 | 修复边缘颜色污染与 Alpha；不能只反复收缩轮廓，把描边和细枝删掉 |
| 高光、白色纸张、皮肤被误删 | 与原图配准，标记必须保持不透明的实体内部与高光区域，检查非预期内部透明孔 | 恢复原始前景 RGB，仅用外轮廓约束实体；不能按“接近背景色”全局挖空 |
| 杯把等内部镂空未去除 | 明确标注每个真实孔洞，在三底色上确认透出底色；检查孔洞数量及内部锚点 Alpha | 单独建立孔洞路径或背景种子；不能默认“封闭区域都是前景”，也不能默认“亮区都是孔洞” |

先写出前景/背景/不确定边缘三类区域：实体核心与高光属于前景，外部和确认过的杯把孔属于背景，抗锯齿混色边界属于待求解区域。原生轮廓路径只自动提取外边界，内部孔洞必须由语义清单确认；对盾牌、拳头等实心物体，非预期内部透明岛应直接报错。细小分离装饰是否保留需要和原图逐个核对，不能按面积统一删除。

Alpha 和边缘 RGB 是两个问题。背景混色满足 C = αF + (1−α)B；仅改变 α 仍可能把原背景颜色留在 F 中。复杂混色边缘交给支持边缘去污染的抠图/图像编辑流程，或保留经过审核的原生描边；没有可靠背景估计时不要用公式强行反推并声称精准。

建立可执行语义合同，例如奖杯应有两个孔洞且杯面高光不透明，拳头和盾牌没有内部透明孔。合同采用与候选实际尺寸一致的坐标，包含 size、keep、holes、outside 及可选 expectedEnclosedHoles；每个区域包含 name 和 box:[x,y,w,h]。对预期为一个连续主体的素材增加 `componentPolicy:{minCount:1,maxCount:1,tinyComponentMaxPixels:N,maxTinyComponents:0}`；合法火花、叶片或分离零件按原图记录允许数量，不能强制写成 1。运行 `scripts/audit-cutout.py candidate.png contract.json --out semantic-report.json`，检查高光丢失、孔洞未透明、意外透明岛与孤立背景碎片。所有锚点必须来自已经查看的原图，不能挑选方便通过的区域。候选移动、缩放或重新生成后先重新配准；尺寸一致本身不证明配准正确。

需要平滑边缘时，可在合同中添加 `edgePolicy`：`minPartialAlphaPixels` 和 `minPartialAlphaBoundaryFraction` 拒绝只有 0/255 的硬阈值边；`forbiddenMatteColors:[{name,rgb:[r,g,b]}]`、`matteDistance` 和 `maxMatteFraction` 拒绝已从原图取样确认的旧底色。再用 `minPartialAlphaLevels`、`maxAbruptTransitionFraction`、`maxIsolatedPartialAlphaFraction`、`maxSinglePixelSpurs`、`maxSinglePixelNotches` 检查 Alpha 梯度量化、突跳、孤立半透明点、单像素尖刺和针孔。所有阈值属于单个素材合同，像素画必须显式声明其边缘策略，不能直接套用普通插画阈值。已知底色检查没有命中，只能证明这些已知颜色没有残留，不能证明任意残色都不存在。

平滑检测以 Figma 主组件的原生 4× 导出为准。若只在 1× 检查，缩小采样可能把锯齿、细小残边和针孔藏起来；若用本地软件二次放大，则可能制造虚假的平滑。检测出尖刺/针孔时先回到 Alpha 路径修补，不得用模糊滤镜覆盖；检测出 Alpha 层级过少或突跳过高时，优先高分辨率重抠或矢量边界重采样，并再次执行高光、孔洞和源 RGB 门禁。

`maxMatteFraction` 要用正反样本校准。合法高光可能在少数边缘像素上接近纸张白，不能因为 2–3 个孤立像素就删除高光；连续白边通常覆盖较长边界。保留一个已目视确认的干净正样本和一个带连续残边的失败样本，选择能让前者通过、后者失败且仍留出明显间隔的阈值，并记录命中像素数与比例。阈值调整后必须重新跑两类样本，不能只让当前候选通过。

脚本不能自动证明没有残色或锯齿：边界半透明统计只用于发现硬阈值嫌疑。几何、颜色、语义、放回组件的效果四项均需通过。测试集至少保留一个实心高光图标、一个带真实孔洞的图标，以及一个细枝/细描边图标；用已知失败素材验证检测器确实拒绝它们。

### 重抠或重生的提示约束

一次处理一个图标，提供未误删细节的原始局部，而不是有缺陷的透明候选。提示词写明：保持轮廓、方向、比例、纹理和全部高光；列出必须透明的真实孔洞；禁止把亮色当透明；输出真实 RGBA、外部和孔洞为零 Alpha；边缘抗锯齿且没有原底色污染；禁止棋盘格、底板、新增阴影和装饰。必要时请求适合平滑边缘的较高分辨率，然后在 Figma 按目标尺寸验收。

提示词采用可核对的分区清单，避免只写“精确抠图”：`必须保留` 逐项列出白色/金色高光、浅色纸面、皮肤、细枝、描边、分离的旗杆或火花；`必须透明` 逐项列出画布外部、杯把孔、工具握柄间隙、叶片间隙；`禁止新增` 列出底板、棋盘格、光晕、投影、描边和重画纹理。要求原对象在目标画布中的中心、尺寸、方向和透视不变，输出 RGBA 且透明区 Alpha=0。若模型仍把高光扣走、把孔洞填实或改变造型，直接转为原像素矢量遮罩/混合方案，不在同一失败提示上反复堆叠形容词。

提示词不是验收证据。即使模型把棋盘格画进杯把，看起来像镂空，只要实际文件为 RGB 就拒收。重生图还要单独检查形状和风格漂移；透明质量更好不能抵消保真度下降。连续同类失败时换方法，不重复只添加“更透明、更精确”的措辞。

透明输出优先使用图像接口的结构化参数，详细流程见 [transparent-generation.md](transparent-generation.md)。提示词负责主体、风格、小尺寸可读性与 Alpha 语义，不能替代 `background: "transparent"`。若当前内置工具未暴露透明参数，允许在提示中请求真实 RGBA，但生成后必须读取文件通道；RGB、烘焙棋盘格、主体整体半透明都立即拒绝，并从原始参考重新生成。不要把失败的棋盘格图继续作为编辑目标，因为后续编辑可能复制棋盘格和污染边缘。

### 干净边缘与原图内区合成

重新生成的图形边缘合格但纹理漂移时，保留它作为干净边界底层；根据实际污染宽度和缩放滤波范围建立安全内区，只把已确认干净的旧 RGB/Alpha 作为上层恢复，不能把固定内缩一像素当作无污染保证。旧素材误删的高光保持为空，由底层补回；旧素材误填的真实孔洞必须在上层遮罩中明确排除。合成后重新导出 1× PNG，重复语义合同与三底色检查，再用整稿原坐标区域比较保真度。只有透明门禁不回退且原图区域误差下降时才替换主组件。

这个方法适合“旧内区基本正确、边界有污染”的素材。若旧图内部也混入背景、对象有细枝被整体误删，或生成候选轮廓明显漂移，应退回重新分割或逐图重生。Figma 的 SVG 子节点坐标在导入时可能被归一化；替换已有子节点 `vectorPaths` 时不能把原画布绝对坐标再次叠加。应按原 `viewBox` 重建整棵 SVG 遮罩，或显式校正变换后再验收。

生成图的 RGB 层与 Alpha/矢量轮廓必须使用同一套配准。若用比生成图前景更大的源图轮廓去遮罩带白底的生成 RGB，轮廓多出的区域会把白色外部重新露出，形成一圈抗锯齿良好但颜色错误的白边。不能把“有半透明边缘”误判为“边缘干净”。先确认生成前景覆盖整个遮罩，再在白、黑、洋红三底色上检查；任何一底出现连续浅色或旧底色环带都拒绝。主组件自身尺寸是合同边界时开启 `clipsContent`，再导出主组件本体，确保内部生成层没有靠越界像素改变组件导出尺寸和实例占位。

若旧素材的边缘颜色已经目视干净，问题仅是二值 Alpha 阶梯，可以在 Figma 内做最小亚像素重采样，不必重生图标：隐藏旧的二值轮廓底层，将透明位图在原组件中心等量扩展约 0.25 px，并裁剪到原组件边界。先在代表性细枝、浅色实体和实心物体上测试，再导出全组。验收需证明：实际宽高不变；出现足够的半透明边缘像素；Alpha 128 阈值轮廓与旧版一致；内部 RGB 变化受控；三底色无连续残边。0.5 px 等较大参数可能让内部纹理重采样并提高整稿误差，应比较整页后保留最小有效参数。若原边缘本来就有旧底色，重采样只会软化污染，必须改用去污染、干净边界或重生方案。

切图清单还应检查连通分量。与主体脱离的小片可能是星光、文字或相邻装饰误入，也可能是应保留的叶片、发丝或工具零件。只能在原图对位确认后排除；记录移除像素数与轮廓 IoU，不能用统一“小面积删除”规则。可在 Figma 原生矢量遮罩中删除已确认的独立子路径，保留位图本身不变。

对象本身含合法分离零件时使用复合遮罩：主轮廓负责主体，每根旗杆、火花、叶尖、杯把或远离主体的小装饰用单独子路径。主体路径外扩不能代替子路径，因为大范围外扩会把旧背景一起带进移动组件。放回 Figma 后导出正常、移动、隐藏三态；隐藏态原位置仍有碎片就记录其包围盒并补对应子路径，移动态出现直边天空块或底板块则缩小该子路径。内层清除遮罩应略小于原像素保护遮罩，使默认状态不混入生成背景的边缘颜色。

### 修复回归

每轮保存原始局部、失败候选、缺陷位置/类型、所用方法与提示词、实际 Figma 导出、语义合同结果和三底色截图。先修少量代表性图标，用原图对位检查；通过后再扩展到同类素材。更新主组件前先验证候选，更新后再次检查所有实例与真实底板。只通过 Alpha 或几个锚点时，状态必须保持待视觉复核。

1. 逐图标导出或读取 PNG，记录来源、sha256、像素尺寸、原图坐标及节点 ID。不要把整张透明图集的检查结果套给每个子图；图集中的局部可能仍有底色。
2. 运行 `scripts/audit-alpha.py icon.png --out alpha-report.json`。没有有效透明通道、所有像素不透明、空图、尺寸不符均失败；PNG 扩展名、RGBA 模式本身不能作为通过证据。调色板 PNG 的 tRNS 透明也有效。脚本只给出必要条件，不自动判断已抠干净。
3. 在 Figma 临时检验 FRAME 放置白色、黑色、洋红色三个底板，上方分别放同一图标实例，100% 和 400% 查看外轮廓和内部孔隙。确保图标自身 FRAME 无填色，导出只包含前景。三种底板不得打包进图标组件。
4. 保留三底色截图和审核记录，逐项确认：没有矩形底色、假棋盘格、白边/黑边/彩色残边、缺失前景、烘焙文字。原始像素细节和 1 px 定位也须比对。
5. 再放回实际组件。隐藏图标时底板完整，隐藏底板时仅剩图标前景；更改底板颜色不能暴露原底色。通过后才复用相同素材的实例。

## 构建字段

原始 `crop` 仅表示矩形取样，不提供透明保证。计划中的图标标记 `requiresTransparency: true`；批处理拒绝以原始 crop 创建它。先完成素材/矢量遮罩和真实 Figma 验收，再写入。不能删除标记绕过检查。

已验收独立透明位图使用 `transparentAsset: "asset-key"`，去掉 `crop`，在 state.assets 中关联 `imageHash`、`sha256`、`alphaReport` 及 `visualReview`。alphaReport 为脚本读取该实际 PNG 的报告；visualReview 包含 status="pass"、backgrounds=["white","black","magenta"] 和 evidenceFiles 三底色实际截图路径。上传后核对 imageHash 与该 PNG 的关联。报告不能手写为通过，引用文件必须实际存在并经查看。

`visualReview.checks` 必须逐项记录 `smoothEdges`、`noMatte`、`highlightsPreserved`、`holesCorrect` 的审核结果，只有全部为 `pass` 才允许构建。存在 `semanticContract` 时，还必须关联 `semanticReport`；它应来自该候选实际文件，`imageSha256` 与素材哈希一致且 `pass=true`。语义检查通过不替代四项视觉审核。

原生矢量遮罩由专门的 Figma 构建代码处理，不能假装透明 PNG 填入 transparentAsset。同样导出独立前景并运行 Alpha/三底色验收。通用批处理只覆盖已验收透明位图，未覆盖的遮罩构建不是已完成项。
