# 验收：画风与排版优先

## 默认目标

图标、场景和最终界面以实际使用尺寸下约 **8–9 分视觉相似** 为完成目标。分数是人工定性判断，不是像素相似率，不要求必须达到 9 分。不要为不可见的像素、纹理或曲线差异反复生成、抠图和调参。

以下两项优先，不能被其他项目的平均得分抵消：

1. **美术风格与参考完全一致**：统一色板与明暗关系、描边、材质、光照、造型和细节密度。允许局部色值和纹理变化；不接受手绘变塑料 3D、柔和色板变霓虹、或同组素材各用一种画风。
2. **排版准确，无非预期溢出**：保留画布、主要区域比例、阅读层级、对齐、间距、换行及图标标签关系。文字和必要内容完整可见，无裁切、越界、遮挡。按 [layout.md](layout.md) 检查，不能靠裁剪内容掩盖问题。

## 默认验收标准

| 项目 | 通过标准 | 可接受的非阻塞差异 |
| --- | --- | --- |
| 整体与图标 | 主要剪影、主体身份、方向和关键部件对应参考，约 8–9 分像 | 细小纹理、轻微曲线和局部材质细节变化 |
| 画风 | 与整张参考和同组素材的美术语言一致 | 不改变画风的局部 RGB 差异 |
| 排版 | 区域尺度、视觉中心、基线、内边距、行列关系准确且完整显示 | 不影响关系的少量位置差异，不设全局 1 px 门槛 |
| 文字与功能 | 文案、数字、单位和状态正确；要编辑的文字为原生可见 TEXT | 风格接近且排版正确的替代字体字形 |
| 透明素材 | 真 Alpha，主体完整，目标尺寸换底正常，无明显残底或孔洞错误 | 接近不透明的实体、正常柔边、极端放大才可见且不影响使用的细小边缘差异 |
| 结构 | 语义单元共同成组；同形背板为同一主组件的实例，前景分离；参考图未充当整屏交付 | 单次装饰用独立 FRAME/图层而非强制主组件 |
| 图形来源与变换 | 可见美术来自生成资产或用户指定复用；倾斜 UI 用摆正母版、局部排字、父容器整体旋转 | 技术遮罩、容器、布局仍原生；素材固有姿势保留 |
| 按钮占幅与文图关系 | 实际主体达到目标尺寸，空白外边不参与布局；文字在背板可用区内视觉居中，字高/字重/间距协调 | 工具画幅限制导致原始母版空白较多，但已保存紧边派生图或正确补偿布局；参考有依据的小幅光学偏移 |

## 默认验证步骤

1. 导出最终根节点 1× 图，确认画布尺寸一致，实际查看整屏和标题、列表、数值、按钮等关键区域。
2. 按 layout.md 检查文字、容器、间距与遮挡。按钮抽查 canvas/body/content/字面框的坐标系、依据、置信度及目标 1× 实际效果：主体没有因外边距缩小，主体比例与参考相符，文字没有偏向空白画布中心，也没有字号/字重不协调。参考字面若由阈值辅助测量，确认浅色笔画和描边未漏；最终以 Figma 原生 TEXT 导出复核。疑似裁切要核对真实内容边界，不能凭截图“没有露出去”判断通过。
3. 逐个透明素材运行基本 Alpha 检查，并查看真实 UI 底色及白、黑、洋红底，可集中成一张证据图。先看目标尺寸，明显问题再放大。
4. 核对关键文字、组件和可编辑属性。按 [asset-assembly.md](asset-assembly.md) 抽查可见图形生成来源、0°/旋转后字图关系、标题行整体移动、共用背板与前景分别隐藏。共享背板同时核对主组件引用与图片内容；图片相似或外层组件类型正确都不足以证明复用。发现问题再扩大范围。结构脚本不自动证明排版无溢出或素材摆正。
5. 简要保存 `styleMatched`、`layoutAccurate`、`noUnintendedOverflow`、`contentComplete`、`visualSimilarity`（人工定性）、`transparentAssets`，以及 `graphicProvenance`、`orientationAssembly`、`semanticGrouping`、`sharedParts`；存在按钮/标签时增加 `subjectFit`、`labelPlacement` 的检查范围与证据。未执行的项明确写未验证。上述错误不能以整体约 8–9 分或 Alpha 通过豁免。

Figma 导出要记录实际节点 ID；本地图不能声称是 Figma 实测。仅交付本地图标时完成本地审核即可，明确 Figma 未测，无需为了报告重建完整 UI。

默认不强制 MAE、像素热图、字体穷举、全部节点移动、逐图标 4× 导出或语义合同。它们用于定位真实问题；已运行的数值报告保留原样，说明是否影响当前视觉目标，不因未启用的严格像素约束失败就拒收视觉合格素材，也不伪造脚本通过。

## 严格模式：仅在明确要求时

用户明确要求逐像素一致、源像素不变或数值阈值时，才启用并记录 `strictPixelScope`。`assetMethod: source-preserve` 不等于选择严格模式。

优先遵循用户阈值。没有指定数值时，可对明确的严格区域使用锚点偏差 ≤1 源像素、RGB MAE ≤3/255、最大通道差超过 16/255 的像素比例 ≤1% 作为诊断目标。`sourceRgbIntegrity` 只约束明确要求保留的可靠前景内区，不套到普通重绘或局部去底编辑。

运行 compare.py 时保留未经自动对齐、裁边、缩放或模糊美化的结果。不得拿参考图与自身比较冒充 Figma 结果。严格失败如实报告；默认 8–9 分不能覆盖用户当前明确的严格要求。

## 完成与返修

先修画风漂移、内容缺失和排版/溢出，再修目标尺寸下可见的模糊、残底。达到默认目标即停止；仅剩轻微差异时报告“满足复刻目标”并按需备注，不继续追逐 10 分。

真实外部阻塞、关键内容缺失、画风不一致、非预期溢出及不透明文件冒充透明仍须明确指出。预算用尽保存最好候选，不无限重复同样失败。

## 交付画布清理门禁

按 [SKILL.md 的交付前清理 QA](../SKILL.md#交付前清理-qa必做) 完成清理后，才可报告交付完成。任务区域只保留全部正式组件、最终拼装界面及必要组织容器；本任务的字体样例、测试/调试副本、换底和对比板等 QA 产物必须从 Figma 删除，隐藏或移到其他页面不算通过。本地证据可保留。记录 qaCleanup：删除的节点 ID、保留的正式根 ID、页面树核对结果，以及清理后实际根节点导出与组件/文字/实例引用检查结果。
