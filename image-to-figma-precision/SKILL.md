# 图片到 Figma 精确分层还原

目标是同时交付视觉接近原图、组件独立、文字可编辑的设计。三者分别验收，不能以视觉相似掩盖结构失败。保持原图设计；不美化、不替换主题、不擅自改文案。

## 启动与取证

1. 读取原图，记录真实像素宽高、哈希、颜色空间、透明度。以原图像素为坐标系，Figma 1 px 对应原图 1 px。禁止靠展示缩略图估计最终尺寸。
2. 确认当前连接后端。Figma Console MCP 本地模式读取 [references/local-console.md](references/local-console.md)；只有使用官方 Figma 插件时才读取其已安装的 `figma-use`、`figma-generate-library` 和 `figma-generate-design`。官方插件卸载后，不将缺少这些附带技能误判为本地 MCP 不可用。没有实际可调用的写入工具时保留成果并明确阻塞，不能宣称已写入。
3. 只读检查目标文件、页面、现有组件与字体。优先使用匹配的本地组件；现有库与图片不一致时，以用户指定的图片为准。图片任务无需扩展成整套品牌库或重新设计暗色模式。
4. 保存 `manifest.json`、`state.json`、`iterations.json` 到当前任务目录。记录源图、文件 key、页面/根节点 ID、创建的全部 ID、素材来源、字体替代和待解决误差。恢复任务先读状态，再查 Figma，避免重复创建。

## 先拆解，后建图

使用 [references/reconstruction.md](references/reconstruction.md) 制定分层和素材计划。

- 建立树：屏幕 → 场景/资源栏/标题/面板/导航 → 单个组件 → 背景/边框/装饰/图标/文字/状态。每个视觉对象必须能追溯到 manifest 中的稳定 key。
- 每个按钮、卡片、资源项、导航项、徽章、进度条均为独立 COMPONENT 或 INSTANCE。重复结构只建一次主组件，用 TEXT、BOOLEAN、INSTANCE_SWAP 属性暴露内容；仅有一份的复杂组件也需要独立容器。
- 文字逐条抄录，记录标点、空格、大小写、数量单位、换行、坐标、字体候选、字号、行高、字距、颜色、描边和阴影。所有可见文字包含图标中的数字徽章，都必须是可见原生 TEXT。不得描边转曲、SVG path 文字、截图文字加透明 TEXT 覆盖。
- 背景分为原生平面（填色、渐变、圆角、描边、投影）、装饰矢量、独立绘画素材。不得把一整张卡片或含字按钮裁成图片，冒充完成组件化。
- 原图不能确定的内容写入 uncertainty：字体身份、遮挡边缘、不可读字符、非整数几何。先执行证据充分的部分；不要用无依据的猜测填入事实字段。

## 素材与自动补全

优先沿用源像素或用户提供的原始素材；图像上传后在 Figma 用 IMAGE 填充、裁剪变换和矢量遮罩隔离对象。遮罩必须沿对象轮廓，不允许把邻近文字或别的组件一起带入。

图标前景必须具有真实透明背景，底板、投影、描边和通知徽章分别建层。矩形裁剪、圆角裁剪、与当前底板同色的底色、画在图片里的棋盘格都不等于抠图。按 [references/transparent-icons.md](references/transparent-icons.md) 的固定闭环检查 Alpha、细小孔隙和边缘杂色，并用 `scripts/render-cutout-proof.py` 生成白、黑、洋红、青色、Alpha 与半透明边缘证据图。未通过的素材不得写入最终图标层；保留问题记录，继续更换方法。

出现旧底色、邻接物颜色或白/黑边时，先读 [references/edge-cleanup.md](references/edge-cleanup.md)：将可靠实体内区、背景/孔洞和混色边带分开，提示词明确只修受污染边带 RGB；透明生成不夹带“失败就用白底”的分支。Alpha 与边缘 RGB 分别验收，包括孔洞内沿和已被误判为不透明的残色边。已知纯色底可用独立 Alpha 反混色；颜色距离 Alpha 不作为默认答案。

抠图须分别验证边缘平滑、原底色残留、高光保留和真实孔洞。对容易混淆的图标建立必须保留/必须透明区域，用 `scripts/audit-cutout.py` 回归检查；不能仅凭有 Alpha 判定合格。平滑边必须用 Figma 主组件原生 4× 导出检查半透明 Alpha 层级、Alpha 突跳、孤立半透明点、单像素尖刺和针孔；`alphaCoverage.minOpaqueFractionOfForeground` 还必须拒绝“背景透明但主体整体半透明”的伪合格图。像素画素材要在合同里显式声明边缘策略。用户允许重新生成时，按 [references/transparent-generation.md](references/transparent-generation.md) 先在生成阶段约束目标尺寸、颜色风格、轮廓风格、主体 Alpha 和孔洞；保留原素材与新候选，分别报告透明质量和原图保真度。重生后需要重新配准，不能改原验收坐标掩盖形状漂移。

轮廓可能由主体、旗杆、手柄、火花等多个不相连区域组成。先建主体外轮廓，再用独立子路径覆盖每个确认属于对象的分离部分；内部孔洞使用反向子路径或显式排除区，不能用一个大矩形把周围背景一起带走。每次更新都导出“正常、移动、隐藏”三态：正常态查边缘变色，移动态查带走的背景块，隐藏态查原位置残留。发现残留后在原位置与无对象补全图之间做局部差分，只扩展命中的子路径，直到没有旗杆、棕榈、高光或描边碎片。

当重生图边缘合格但内部纹理偏离时，可采用“干净候选底层 + 旧素材安全内缩区覆盖”的混合方案。旧层只覆盖经形态内缩确认的实体内区，真实孔洞必须显式排除，误删高光由底层补回。候选、混合结果和实际主组件都要各自导出检查；整稿局部误差没有下降时回退，不因边缘变干净就忽略保真退化。

混合方案中的颜色层和轮廓必须同坐标、同覆盖范围。不能用较大的源轮廓遮住仍带白色外部的生成 RGB，否则会制造连续白边。已知底色阈值用干净正样本和残边负样本共同校准，调整后两者都要回归。主组件含越界的生成层时，将主组件裁剪到已审核的组件尺寸，再审计实际 Figma 导出；候选文件通过不能替代线上导出通过。

旧透明素材若只有二值 Alpha、边缘 RGB 已确认干净，可在 Figma 中对位图做约 0.25 px 居中等量扩展并裁剪到原组件边界，用最小重采样恢复亚像素边。必须同时记录半透明像素数、阈值轮廓 IoU、内部 RGB 变化和整页指标；更大参数造成内部纹理或整页误差回退时改用最小有效参数。该方法不能修复旧底色污染。发现孤立碎片时，只有与原图对位确认它来自相邻装饰后，才从原生矢量遮罩中删除对应子路径。

需要去字、去底、抠图或补画时使用可用图像编辑工具。只补局部缺失，约束原尺寸、可见轮廓和光照；保存原图、生成图和区域坐标。推断补全不得替换可保留的原始可见像素；已确认混入背景色的边带按边缘去污染协议处理，不要求保留污染 RGB。复杂插画可保留独立位图素材，但不是每个像素都要矢量化。

遮挡恢复属于推断，不能声称找回原始隐藏像素。补全层命名 `Inferred/…`，在素材记录中注明模型生成。组件移动/隐藏后应有合理底板，不应露出残留文字、矩形截断或复制的另一份对象。见参考中的“移开测试”。

大型场景对象优先采用“原始可见像素前景 + 局部推断遮挡底板”：底层保留原场景，推断图只通过内缩遮罩覆盖对象原位置，最上层的独立组件用稍大的保护遮罩显示同坐标原始像素。默认状态由原像素完全盖住推断区，避免生成图改变高光和纹理；移动或隐藏组件时才露出补全底板。保护遮罩必须比补全遮罩大，且三态均要导出，否则遮罩抗锯齿会在默认状态混入生成颜色。

场景前景必须额外导出主组件本身的 4× RGBA PNG 验收，不能只看默认整屏。透明导出里出现道路、草地、天空、人物或相邻建筑，即使默认整屏逐像素不变，也按背景夹带失败处理。为每个对象建立 `audit-cutout.py` 合同：`keep` 覆盖主体、高光、细杆和装饰，`outside` 覆盖已确认的背景与相邻对象，`holes` 覆盖栏杆、把手和建筑开口，`alphaCoverage` 限制异常大块或异常缺失，`componentPolicy` 限制意外连通块和细小背景碎片。使用 `--source` 时还要启用 `sourceRgbIntegrity`，确认高 Alpha 区仍是配准后的源像素。

自动分割模型只生成候选 Alpha。先对同一个原始裁片测试至少一个通用模型和一个适合该画风的模型，再逐对象选择；禁止按整批统一接受。模型输出必须与人工外轮廓取交集，并通过保留区、透明区、孔洞、边缘与源 RGB 五类检查。若主体内部被降为半透明、阴影/烟雾消失、人物被误连、或整屏局部 MAE 回退，立即拒绝。RGB 输出、烘焙棋盘格、改尺寸、重绘几何的生成结果不能充当 Alpha。

模型、矢量或混合候选应用到正式画板后，依次导出：主组件透明图、默认整屏、全部隐藏、分别移动。默认整屏必须先与当前稳定基线比较，再与设计稿比较；透明更干净但默认画面退化时回滚。移动图相对隐藏图的变化只能出现在移动后的对象轮廓内，原位置不得出现对象残影。所有失败候选记录模型、提示词/参数、失败门禁与回滚哈希，避免下一轮重复误收。

## Figma 构建

- 在用户指定文档的新页面或明确空白区域工作。组件库、原图参考和最终屏幕分开；原图参考不嵌套进交付屏幕。
- 破坏性批量变更前调用 `figma.commitUndo()` 建立独立撤销边界。清理临时节点只按账本 ID，并显式保护页面、根画板、场景根和组件库；不能让根节点复用临时子层的清理标记。删除主组件前先删除它的实例，失败后先只读核对固定根 ID/尺寸/文字数/实例数。若必须 `triggerUndo()`，随后重新核对并按证据重放被一并回退的标定，不能假定只撤销最后一条语句。
- 先建少量实际需要的颜色/文字/效果变量或样式，再建原子组件。不要为单张图生成无关模式、页面和变体。
- 精确静态重建允许绝对坐标与自由叠放；有规则的行列使用固定尺寸 auto-layout。不要为了自动布局改变原图中的非均匀间距。
- 依赖顺序：底板 → 图形素材 → 独立组件 → 原生文字 → 实例组装。背景、边框、光泽、阴影、图标、标签必须分别可选；进度轨道、填充值、数字必须独立。
- 列出可用字体并加载真实 family/style 后才编辑文字。字体候选至少用短中文标题和数字样例截图比较；记录替代，不凭“加载成功”判定正确。尺寸以实际渲染包围盒校准，不以 CSS 字号或字体名称等价推断。
- 字体家族筛选后仍需做参数图集：在临时克隆中隐藏目标 TEXT，导出同一 family/style 下的字号、字距、描边候选，再按原坐标合成到无字背景，搜索整数位移并用目标局部 MAE 排序。必须保留当前参数作为基线，最终把候选写回主组件后再导出整屏；局部改善但整屏回退时撤销。重复数值、速率、行标题和导航标签先用一个代表项标定，再逐项校正左侧字面边界，不能把同一个 x 偏移机械套到不同字符串。
- Figma 的 `resize()` 可能只改变 INSTANCE 外框而不缩放内部图形。需要等比测试实例内容时使用 `rescale()`，并导出候选验证实际 Alpha 包围盒确实变化；所有候选导出相同说明测试无效，不能据此保留尺寸。交付中只缩放实例，不为匹配父布局破坏已经通过透明门禁的图标主组件。
- 分小批串行修改。每批返回所有创建/修改 ID，立刻写状态。创建前按已记录 ID 和确定名称查重；错误先查原因和现场，再修正。超时不等于失败，禁止盲目重发导致重复。
- 主组件不能直接嵌套主组件。先在 FRAME 中构建子树，再从最内层开始转为主组件，将主组件移到组件库，在原位置放入 INSTANCE；最后处理父组件。转换和实例化会改变后代 ID，立即重新遍历并更新账本与文字清单。
- 可用 [scripts/componentize-one.js](scripts/componentize-one.js) 执行单个容器转换；调用约定见 [references/plan-format.md](references/plan-format.md)。转换前确认子组件已完成，转换后重新导出比较，不能只凭节点类型变化判定通过。
- 若截图 URL 返回非图片（例如 202、零字节或网站防护 challenge），校验 Content-Type、PNG 文件头和字节长度；使用工具提供的 inline/base64 图片能力，不把空文件计为截图。调用额度耗尽属于外部阻塞，停止无意义重试；已成功写入的进度继续保存。
- 使用 [scripts/audit-figma.js](scripts/audit-figma.js) 的审计函数检查目标根节点。必须把结果保存到文件，不只打印“通过”。

批量构建可使用 [scripts/prepare-batch.py](scripts/prepare-batch.py) 和 [scripts/apply-batch.js](scripts/apply-batch.js)。先读 [references/plan-format.md](references/plan-format.md)。准备器只生成待审核的工具代码，不会自动写入 Figma；成功执行后将返回 mapping 合并进状态，再准备下一批。该模板提供基础平面/文字/裁剪能力，复杂遮罩、auto-layout 和组件实例转换需要按拆解计划继续执行，不代表运行完模板就通过验收。

## 验收与迭代

读取 [references/acceptance.md](references/acceptance.md)。导出 Figma 最终根节点 1× PNG，确认尺寸完全一致。使用 `scripts/compare.py reference.png candidate.png --regions manifest.json --out iteration-01` 产生全图/区域误差、叠加图和差异图。不要缩放、自动对齐、裁边或模糊候选来美化指标。

分别检查：

1. **结构**：所有清单组件存在、每条文字为原生可见 TEXT、所有图像无烘焙文字、重复项使用实例、节点可编辑、无未完成 placeholder。
2. **局部视觉**：每个关键区域 100% 和 200% 检查轮廓、边距、字形、进度终点、阴影、渐变、遮罩漏底。
3. **整体视觉**：1× 同尺寸叠加比对；场景面积不能稀释按钮/文字误差。指标是诊断，不自动等同“相似率”。
4. **可编辑性**：在临时副本更改标题、数值和进度、隐藏图标、移开组件；检查原字是否残留、背景是否完整、同类实例是否正确更新。恢复后重新导出验证。只删除账本中明确属于本次测试的副本 ID。

每轮记录问题 → 证据 → 最小修改 → 新截图/新指标。优先纠正尺度/位置，其次文字、形状、素材边缘和色差。若某轮没有改善，改变方法（字体候选、遮罩、原生渐变、局部素材），不能无意义重复同一提示。

未通过严格检查继续迭代。若遇到真实外部阻塞或原图信息不足，保存最优版本和剩余差异，准确报告“未达到精准还原”，不要伪造 100% 或降低阈值宣布完成。最终交付 skill 路径、Figma 根节点链接、截图、测试报告、位图/原生层边界及未解决项。
