# 图片到 Figma 分层复刻

默认目标是图标和最终界面都达到约 **8–9 分视觉相似**，在实际使用尺寸下看起来属于同一套设计即可完成，不追逐逐像素一致。分数是人工视觉判断，不是 MAE 换算的相似率，不要求每个对象都达到 9 分。

**美术风格必须与参考一致，排版准确、无非预期溢出是交付重点。** 统一色板、描边语言、材质、光照、造型和细节密度；保持布局层级、主题、语义、文案和可编辑性。允许轻微轮廓、纹理、局部色值及替代字体字形差异，不为实际尺寸下看不出的差异反复返工。明显风格漂移、内容缺失、文字裁切或组件互相遮挡不能用整体评分抵消。

只有用户明确要求逐像素一致、源像素完全不变或指定数值阈值，才启用 [references/acceptance.md](references/acceptance.md) 的严格模式。`source-preserve` 表示素材来源策略，本身不触发严格验收。

**最终交付前必须完成 [QA 清理](#交付前清理-qa必做)，Figma 中只保留全部正式组件与最终拼装界面。**

## 启动与取证

1. 读取原图，记录真实像素宽高、哈希、颜色空间、透明度。以原图像素为坐标系，Figma 1 px 对应原图 1 px。禁止靠展示缩略图估计最终尺寸。
2. 确认当前连接后端。Figma Console MCP 本地模式读取 [references/local-console.md](references/local-console.md)；只有使用官方 Figma 插件时才读取其已安装的 `figma-use`、`figma-generate-library` 和 `figma-generate-design`。官方插件卸载后，不将缺少这些附带技能误判为本地 MCP 不可用。没有实际可调用的写入工具时保留成果并明确阻塞，不能宣称已写入。
3. 只读检查目标文件、页面、现有组件与字体。复用用户指定或本任务已生成并验收的匹配组件；其他现有组件可作为结构参考，不能自动绕过生图要求。现有库与图片不一致时，以用户指定的图片为准。图片任务无需扩展成整套品牌库或重新设计暗色模式。
4. 保存 `manifest.json`、`state.json`、`iterations.json` 到当前任务目录。记录源图、文件 key、页面/根节点 ID、创建的全部 ID、素材来源、字体替代和待解决误差。恢复任务先读状态，再查 Figma，避免重复创建。

## 先拆解，后建图

使用 [references/reconstruction.md](references/reconstruction.md) 制定分层和素材计划。生成前必须读 [references/asset-assembly.md](references/asset-assembly.md)，先确定美术素材来源、摆放角度、语义分组和共用零件，再开始生图。

- 建立树：屏幕 → 场景/资源栏/标题/面板/导航 → 单个组件 → 背景/边框/装饰/图标/文字/状态。每个视觉对象必须能追溯到 manifest 中的稳定 key。
- 主要按钮、卡片、资源项、导航项、徽章、进度条应能独立编辑。重复结构使用主组件和实例，按需要暴露 TEXT、BOOLEAN、INSTANCE_SWAP 属性；单次复杂对象保留独立容器，不强制每个装饰都转换为主组件。
- 文字逐条抄录，记录标点、空格、大小写、数量单位、换行、坐标、字体候选、字号、行高、字距、颜色、描边和阴影。所有可见文字包含图标中的数字徽章，都必须是可见原生 TEXT。不得描边转曲、SVG path 文字、截图文字加透明 TEXT 覆盖。
- 所有可见美术图形均走参考图生图：包括小菱形、帽子、按钮/标签背板、边框、装饰线、徽章和绘画背景。不得因形状简单、时间不足或原生节点可编辑而手写 SVG/path、拼几何形状替代。原生 TEXT 承担文字；FRAME、布局、无可见填色的技术遮罩和变换承担组装。用户明确指定复用的原素材/组件优先，逐项记录来源；不能自行扩大此例外。
- 先识别共享背板与独立前景、同一条标题行与局部坐标系。按钮/标签等整体倾斜的组件先生成摆正、无字的母版，在局部坐标中排文字及图标，最后旋转共同父容器。不得将摆放倾斜烘焙进底板后叠水平文字。
- 原图不能确定的内容写入 uncertainty：字体身份、遮挡边缘、不可读字符、非整数几何。先执行证据充分的部分；不要用无依据的猜测填入事实字段。

## 美术图形：参考风格与文字共同驱动生成

所有美术图形走 [references/transparent-generation.md](references/transparent-generation.md)，背景按需要使用不透明输出。先实际查看参考图，口述其配色、描边、造型、材质、光照和细节密度；再为每份独立素材写明主体、部件、规范朝向、孔洞、目标尺寸及不属于本素材的相邻零件。参考裁片仅说明主体与风格，不作为交付像素或待抠图对象。

- 保留原有主体语义、关键部件、固有姿态与整套画风；组件在页面上的旋转在组装时恢复，不写入母版。不能把透视、斜切边或道具自身的姿势一律拉正，区别见 asset-assembly.md。整体外形约 8–9 分像即可，不能用该分数接受错主体或用手画占位替代成品。
- 先选一个有代表性的图标生成并验证风格；通过后作为辅助风格参考，逐个生成其余图标，每次仍附原图参考和该图标的专属描述。不生成整页 UI 再裁图标，不生成密集图集后放大切片。
- 按主体比例选择工具支持的母版画幅，按钮/标签不要默认生成在大方形画布中。要求紧凑构图和小幅安全边距；保存实际可见主体框、四边空隙与文字可用区。Figma 按可见主体缩放定位，不能按整张 PNG 的空白外框适配按钮；具体规范见 asset-assembly.md 的“按钮主体边界与文字可用区”。保留高清母版，不把低清裁片插值放大或把 Figma 4× 导出当作新增细节。
- 独立素材默认直接请求真实 RGBA；工具支持时显式传 `background: "transparent"`，并保存实际调用参数。主体及高光接近不透明、正常柔边可以接受；背景和真实孔洞透明。共享底板必须单独生成一次并用同一主组件复用，各前景单独生成且不含背板；不能把重复 UI 边框误写成物体的“固有底座”。物体固有轮廓和材质明暗保留在素材内。
- 不自动退回截图抠图、颜色键、源像素遮罩或“新边缘 + 旧内区”混合方案。风格或清晰度失败时改写描述并从原参考重新生成；达到重试预算就保存候选与未解决项。
- 用 [references/transparent-icons.md](references/transparent-icons.md) 检查目标尺寸的清晰度、语义、画风和真实 Alpha，查看换底效果。透明通过不等于画风通过；目标尺寸正常即可，不默认逐图做语义合同或 4× 边缘审计。复杂孔洞、可见缺陷或严格要求时再深化检查。
- 在 manifest 中记录每项素材的生成方式、参考图、实际提示词、目标尺寸、母版尺寸与审核结果。图标重绘不要求源 RGB 相同；像素差异报告仅在需要诊断或严格任务时生成，并按 [references/acceptance.md](references/acceptance.md) 分别报告重绘质量和像素一致性。

## 场景补全与局部编辑

用户指定保留原素材时优先复用；其余绘画场景与补全通过生图完成，需要补全时只补实际缺失区域，并匹配同一画风。推断层标为 `Inferred/…`，不能声称找回原始隐藏像素。组件移动或隐藏后不应出现明显残字、残影和矩形截断。

普通任务允许不改变画风的局部纹理、轮廓和色值调整，不强制源 RGB 相等、双模型分割或逐对象 4× 审计。用户明确要求对已生成高清候选去底或局部修边时按其请求处理；这不是把低清截图抠图冒充重绘。默认按视觉目标验收，只有明确要求源像素不变时才检查 RGB 完全保留。

出现可见边缘污染时读取 [references/edge-cleanup.md](references/edge-cleanup.md)。复杂遮挡可参考 reconstruction 的双层方案；严格源像素任务再使用语义合同、`sourceRgbIntegrity` 和必要的移动/隐藏导出。不得将这些深度流程套到所有图标或场景。

## Figma 构建

先读 [references/layout.md](references/layout.md)，优先落实主要区域、对齐线、间距和内容边界，再校正细节。

- 在用户指定文档的新页面或明确空白区域工作。构建期间将组件库、临时原图参考和最终屏幕分开；原图参考不嵌套进交付屏幕，交付前按下文清理临时参考与 QA。
- 破坏性批量变更前调用 `figma.commitUndo()` 建立独立撤销边界。清理临时节点只按账本 ID，并显式保护页面、根画板、场景根和组件库；不能让根节点复用临时子层的清理标记。删除主组件前先删除它的实例，失败后先只读核对固定根 ID/尺寸/文字数/实例数。若必须 `triggerUndo()`，随后重新核对并按证据重放被一并回退的标定，不能假定只撤销最后一条语句。
- 先建少量实际需要的文字样式和容器，再用已验收的生成素材建立原子组件。样式、矢量或颜色变量不能作为绕过美术生图的捷径。
- 精确静态重建允许绝对坐标与自由叠放；标题行、图标+标签等语义单元先建共同父容器，再在局部坐标中对齐；有规则的行列使用固定尺寸 auto-layout。不能将同组对象散放在屏幕根节点后分别挪位置。不要为了自动布局改变原图中的非均匀间距。
- 依赖顺序：重复零件识别 → 摆正的共用底板 → 独立前景 → 局部组件及原生文字 → 实例组装 → 父容器旋转。图标、背板、标签分别可选；背板自身的材质/高光可保留在同张生成图内，需要独立编辑或复用的装饰另生图。进度轨道、填充值、数字独立，进度用生成素材配合技术遮罩表达。
- 列出可用字体并加载真实 family/style 后才编辑文字。字体候选至少用短中文标题和数字样例截图比较；记录替代，不凭“加载成功”判定正确。尺寸以实际渲染包围盒校准，不以 CSS 字号或字体名称等价推断。
- 字体替代以画风、字重和排版接近为准；重点校正文字宽高、基线、换行、行高和间距。默认不做字体参数图集或按 MAE 穷举，只有明显字形/排版问题或严格要求时才使用。重复项先校准代表项，再检查最长文案和最大数值。
- 按钮文字在实际背板的可用区内排版，按可见字面而非 TEXT 行框做视觉居中；字号、字重、字距与实际背板高度相配。有动作图标时先确定图标+文字组合的中心和间隔，不能让文字单独挤占图标。先在 0° 校准，最后整体旋转。
- 文字必须完整显示，内容不越出所属容器，相邻组件无非预期重叠。检查 TEXT 的真实内容高度及所有祖先裁剪，不得靠 `clipsContent`、删字、省略号、横向压缩或无依据缩小字体掩盖溢出。参考中已有的装饰出界和遮罩单独记录为有意设计。
- Figma 的 `resize()` 可能只改变 INSTANCE 外框而不缩放内部图形。需要等比测试实例内容时使用 `rescale()`，并导出候选验证实际 Alpha 包围盒确实变化；所有候选导出相同说明测试无效，不能据此保留尺寸。交付中只缩放实例，不为匹配父布局破坏已经通过透明门禁的图标主组件。
- 分小批串行修改。每批返回所有创建/修改 ID，立刻写状态。创建前按已记录 ID 和确定名称查重；错误先查原因和现场，再修正。超时不等于失败，禁止盲目重发导致重复。
- 主组件不能直接嵌套主组件。先在 FRAME 中构建子树，再从最内层开始转为主组件，将主组件移到组件库，在原位置放入 INSTANCE；最后处理父组件。转换和实例化会改变后代 ID，立即重新遍历并更新账本与文字清单。
- 可用 [scripts/componentize-one.js](scripts/componentize-one.js) 执行单个容器转换；调用约定见 [references/plan-format.md](references/plan-format.md)。转换前确认子组件已完成，转换后重新导出比较，不能只凭节点类型变化判定通过。
- 若截图 URL 返回非图片（例如 202、零字节或网站防护 challenge），校验 Content-Type、PNG 文件头和字节长度；使用工具提供的 inline/base64 图片能力，不把空文件计为截图。调用额度耗尽属于外部阻塞，停止无意义重试；已成功写入的进度继续保存。
- 使用 [scripts/audit-figma.js](scripts/audit-figma.js) 的审计函数检查目标根节点。必须把结果保存到文件，不只打印“通过”。

批量构建可使用 [scripts/prepare-batch.py](scripts/prepare-batch.py) 和 [scripts/apply-batch.js](scripts/apply-batch.js)。先读 [references/plan-format.md](references/plan-format.md)。准备器只生成待审核的工具代码，不会自动写入 Figma；成功执行后将返回 mapping 合并进状态，再准备下一批。该模板提供基础平面/文字/裁剪能力，复杂遮罩、auto-layout 和组件实例转换需要按拆解计划继续执行，不代表运行完模板就通过验收。

## 交付前清理 QA（必做）

**最终 Figma 交付区域只保留全部正式组件、最终拼装界面及其必要的组织容器。QA 产物不是交付物，必须删除；仅隐藏、移到远处或转移到其他 QA 页面不算清理完成。**

- 创建字体样例、换底/透明检查、前景与背板隐藏测试、旋转/缩放对比、调试副本、原图对照板等临时节点时，将其根 ID 单独记入 state.qaRootIds；正式组件库、最终根画板及其后代列入保护清单。不能依靠名称关键词批量删除。
- 验证完成后，先把截图、审计结果和对比证据保存到本地任务目录，再按账本 ID 删除本任务创建的全部 QA 节点及其后代，并清理因此留下的空容器/空页面。保留全部正式主组件、组件集、最终界面及其有效依赖；不清理其他任务或用户原有内容。
- 按“Figma 构建”的撤销边界与保护规则执行清理。若临时容器中混入正式组件，先迁回组件库并核对实例引用，再删除临时容器。
- 清理后重新读取任务区域的页面树，确认只剩正式组件与最终界面；核对根节点 ID、尺寸、文字、组件和实例引用未受损，再导出最终根节点并实际查看。将删除 ID、保留根 ID 与检查结果写入 state / 验收记录；本地 QA 证据可以保留。**QA 残留时不得标记交付完成。**

## 验收与迭代

按 [references/acceptance.md](references/acceptance.md) 验收。默认检查：实际尺寸整屏、关键排版与无溢出、必要的原生文字/组件结构，以及透明素材的真实 Alpha 和目标尺寸换底效果。Figma 结果须来自实际根节点导出；本地验证与 Figma 实测分开报告。

先修正画风不一致、排版/溢出和内容缺失，再处理明显模糊、残底。风格一致、布局准确、无非预期溢出、内容完整且整体约 8–9 分相似时即可交付，停止微调；细小差异可以备注，不算返修阻塞。

`compare.py`、全图/区域差异图、字体参数搜索、全部节点移动测试和 4× 导出均按需使用，不是普通任务的必经步骤。若运行严格数值诊断，保留真实结果；仅涉及当前未启用的严格像素约束时，可记为非阻塞诊断，不能改写成脚本通过。

每轮记录明显问题、最小修改和实际证据。图标遵守生成预算与同类失败停止条件，通过就停，不为了满分反复生成。真正阻塞或预算用尽时保存最好候选与具体问题。最终交付成果、截图、使用的 skill、已验证范围及影响使用的未解决项，不因接受轻微差异就标为“未达到精准还原”。
